# GRABBIT — 로컬 중력 퍼즐

Unity 6000.6.0f1. `Assets/Scenes/Grabbit.unity`를 열고 Play를 누르면 **시작 화면**이 표시됩니다.
이번 수정은 Unity 프로젝트에만 적용합니다. Windows 빌드는 하지 않았으며 기존 `Builds/Windows` 실행 파일은 이전 버전입니다.

## 화면 흐름

1. 시작 화면의 **▶ 아이콘** → 스테이지 선택. 홈에는 GRABBIT 로고 외에 부제와 버튼 글자가 없습니다.
2. **숫자 카드** 클릭 → 해당 스테이지를 처음부터 시작. 이름·설명·선택하기 문구를 제거했습니다. 5개씩 표시하고 추가 맵은 아래 화살표로 넘깁니다.
3. 목표 깃발에 도착 → 마지막 이동/회전 연출이 끝난 뒤 0.7초 후 스테이지 선택으로 복귀. 완료한 카드에 체크 표시가 나타납니다.
4. 클리어한 스테이지도 다시 선택할 수 있습니다. 모든 스테이지는 처음부터 선택 가능합니다. 완료 표시는 현재 Play 세션 동안 유지됩니다.

게임 화면 우측 상단의 **세 줄 메뉴 아이콘**을 클릭하면 팝업이 열립니다.

- **게임으로 돌아가기**: 현재 보드와 진행 상태를 유지하고 이어서 플레이.
- **스테이지로 돌아가기**: 진행 중인 연출을 취소하고 스테이지 선택 화면으로 이동.
- **메뉴로 돌아가기**: 시작 화면으로 이동.

팝업 중에는 게임 조작, 시점 조작, 이동/회전 애니메이션, 클리어 복귀 타이머가 멈춥니다. 닫기 아이콘이나 Esc로도 게임에 복귀합니다. 팝업과 맵 제작 도구에는 사용에 필요한 글자가 있고, 실제 게임 화면에는 아이콘만 표시합니다.

## 게임 안에서 맵 만들기

홈 오른쪽 아래 또는 스테이지 선택 오른쪽 위의 **연필 아이콘**을 누르세요. Unity 메뉴 `GRABBIT > Map Maker`에서도 Play와 제작 화면을 열 수 있습니다.

1. **새 맵**으로 시작하거나 **불러오기**에서 기본 스테이지를 복사합니다. 불러오기는 저장한 맵도 보여 줍니다.
2. **블록**을 선택하고 왼쪽 격자를 클릭하거나 드래그합니다. 모든 블록은 이동할 수 있습니다. **지우개**로 제거합니다.
3. 기본 단면 **XZ**에서는 `Y − / +`로 높이를 바꿉니다. **XY / ZY**로 옆 단면을 볼 수 있습니다. 격자 아래 화살표로 표시 범위를 옮깁니다. 보이는 17×17 격자는 편집 창이며 게임의 이동 경계가 아닙니다.
4. **토끼**를 선택해 빈칸 또는 발밑 블록을 클릭합니다. 블록 클릭 시 선택한 발 방향의 반대쪽 빈칸에 놓입니다. 오른쪽에서 **발 방향**과 **시선**을 정합니다. 시선은 발 방향과 직각인 방향만 선택할 수 있습니다.
5. **깃발**을 선택해 목표 블록을 클릭하고 오른쪽에서 **깃발 면**을 정합니다. 깃발은 그 블록에 붙어서 함께 움직입니다. 지우개로 해당 블록을 지우면 깃발도 제거됩니다.
6. **▶ 테스트**로 실제 규칙을 플레이합니다. 왼쪽 위 **연필 아이콘**은 이동 전 편집 배치로 돌아갑니다. 클리어하면 다른 스테이지처럼 선택 화면으로 돌아갑니다.
7. **저장**한 정상 맵은 기본 5개 뒤에 숫자 카드로 추가됩니다. 미완성 맵도 초안으로 저장할 수 있지만 플레이 카드에는 나타나지 않습니다. **다른 이름 저장**은 새 파일을 만듭니다.

### 맵 삭제와 복구

**연필 아이콘 → 불러오기 → 맵 옆의 삭제**를 누르면 기본 스테이지와 직접 저장한 맵 모두 목록과 스테이지 선택에서 빠집니다. **불러오기 → 휴지통 → 복구**로 되살릴 수 있습니다. 삭제와 복구는 게임을 다시 실행해도 유지됩니다.

현재 편집 중인 맵을 삭제해도 배치는 초안으로 남습니다. 이후 저장하면 새 맵으로 등록합니다. 모든 맵을 삭제했을 때는 스테이지 선택 중앙의 연필 아이콘으로 새 맵을 만들 수 있습니다. 저장 맵의 휴지통은 `UserMaps/Trash`, 기본 스테이지의 삭제 상태는 `UserMaps/catalog.json`에 보관합니다.

블록·토끼·깃발 편집은 **되돌리기 / 다시 하기**를 지원합니다. 새 맵과 불러오기도 되돌릴 수 있습니다. 변경 내용은 별도 `draft.json`에 자동 보관되므로 Play를 종료한 뒤 제작 화면을 다시 열어 이어서 작업할 수 있습니다. 저장 버튼을 누른 맵 파일과 자동 초안은 별개입니다.

현재 Unity 프로젝트의 저장 위치는 **`UserMaps/`**입니다. 외부 도구나 Codex도 같은 JSON 파일을 작성할 수 있습니다. 플레이어 환경에서는 `Application.persistentDataPath/Maps`를 사용합니다. **JSON 복사 / JSON 가져오기**로 맵 내용을 공유할 수 있고, 가져온 맵은 저장할 때 새 파일이 되어 원본을 덮어쓰지 않습니다.

JSON은 `version: 1`, `title`, `boxes: [{x,y,z}, ...]`, `hasRabbit`, `rabbit: {cell,down,forward}`, `hasFlag`, `flagBlock`, `flagNormal`, `pitch`, `yaw`를 포함합니다. `id`는 저장 시 자동 생성합니다. 제작 좌표는 ±10,000, 블록은 최대 2,048개입니다. 플레이 중 내려찍기에는 좌표 경계가 없습니다. 시선·발 방향·깃발 면은 6개 단위 축 중 하나입니다.

외부에서 JSON 파일을 추가했다면 게임을 다시 실행하거나 제작 도구의 불러오기 목록에서 열어 저장하세요. 파일명은 저장 시 발급한 GUID를 사용합니다. 직접 JSON을 작성한 경우에는 게임 안의 JSON 가져오기와 저장을 통해 등록하는 방법이 가장 간단합니다.

테스트 전 중복/점유/시작 자세/깃발 접근면을 검사합니다. 무중력 시작은 메커니즘 검증용으로 허용하고 조작 제한을 표시합니다. 이 검사는 퍼즐의 해답 존재까지 보장하지 않으므로 완성한 맵은 직접 클리어해 확인하세요.

제작 도구 검증: `GRABBIT > Run map maker verification`에서 75개 검사 통과. 실제 게임 연결에서는 저장 파일의 스테이지 등록·다음 페이지·테스트·편집 복귀·클리어 복귀·숫자/아이콘 UI 13개 검사를 통과했습니다. 결과는 `Captures/Grabbit-map-verification.txt`, `Captures/Grabbit-maker-ui-verification.txt`에 있습니다. 기존 중력 로직도 75,915개 검사를 다시 통과했습니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| W / S | 토끼가 보는 방향으로 전진 / 후진 |
| A / D | 현재 셀에서 왼쪽 / 오른쪽으로 90도 방향 전환 |
| SPACE | 토끼와 발밑 연속 블록열을 로컬 Down으로 함께 한 칸 이동 |
| Z | 직전 행동 전체 되돌리기. 연출 도중에도 가능 |
| R | 현재 스테이지 초기화 |
| Esc | 게임 중 메뉴 열기/닫기. 스테이지 선택에서는 시작 화면으로 복귀 |
| 1 ~ 5 | 스테이지 선택 화면에서 해당 스테이지 시작 |
| Enter | 시작 화면에서 스테이지 선택으로 이동 |
| Shift 누르기 / 떼기 | 내려찍기 결과 미리보기 표시 / 해제 |
| 마우스 좌측 드래그 / 휠 | 게임 시점 회전 / 확대 |
| C | 기본 각도로 복원하고 현재 보드에 화면 맞추기 |

금색 화살표는 앞, 민트 화살표는 뒤입니다. 키를 유지해도 반복 동작하지 않으며, 게임 조작은 토끼의 로컬 좌표계를 따릅니다. 게임 중 1~5/Tab으로 직접 스테이지를 바꾸던 이전 단축키는 화면 흐름에 맞춰 정리했습니다. 메뉴 버튼 클릭이 카메라 드래그로 전달되지 않습니다.

## 중력 규칙

2026-09-07 사용자의 수정 지시를 기존 `GRABBIT_Local_Gravity_Core_Spec_v1.1.pdf`보다 우선 적용했습니다. 요약기획서의 우주복 토끼, 큐브 행성, 깃발과 쿼터뷰 외형을 유지합니다.

- 토끼는 정수 셀 하나입니다. 여섯 면에 바로 붙은 첫 블록이 있어야 해당 방향이 중력 후보입니다.
- 첫 블록부터 같은 축의 연속열을 첫 빈칸까지 합산합니다. 옆 가지는 더하지 않습니다.
- 빈칸 하나 너머 블록은 길이에 관계없이 중력 0입니다. 원격 중력에 의한 낙하는 없습니다.
- 먼저 같은 축의 양쪽 블록 수를 뺍니다. 예: +X 3개 / -X 1개는 +X 방향 2의 힘, 위 3개 / 아래 3개는 Y축 힘 0입니다. 기존 접촉 보너스는 사용하지 않습니다.
- 상쇄 후 남은 힘이 가장 큰 방향을 선택합니다. 서로 다른 축이 같으면 현재 Down을 유지합니다. 현재 Down이 최대 후보가 아니면 +X/-X/+Y/-Y/+Z/-Z 순서입니다.
- 예외로, 토끼가 같은 최대 힘을 가진 옆면 블록을 바라보고 W를 누르면 현재 셀에서 그 면으로 90도 회전해 섭니다. 블록 내부로 한 칸 이동하지 않습니다. 머리는 새 바닥의 반대쪽, 시선은 이전 머리 방향으로 바뀝니다. A/D만 누르면 고개만 돌리고 중력은 유지합니다. S로 뒤의 면에 갈아타지는 않습니다.
- 모든 축의 남은 힘이 0이면 그 위치에서 무중력 상태가 됩니다. 해당 상태로 진입한 행동을 취소하지 않습니다. W/S/Space는 동작하지 않고, A/D로 바라보기 및 Z/R, 메뉴 조작은 가능합니다. 무중력에서는 이동 화살표를 숨깁니다. 다른 축에 힘이 남아 있으면 그 방향으로 회전합니다.
- 내려찍기는 토끼와 발 방향 연속열을 함께 한 칸 옮기고, 새 토끼 셀에서 중력을 계산합니다. 화면에서도 같은 시간과 보간값으로 이동한 다음 자세를 회전합니다.
- A/D는 위치와 Down을 바꾸지 않고 바라보는 방향만 바꿉니다. W/S 목적지에는 기존 Down 방향의 지지 블록이 필요합니다.
- 모든 블록은 이동 가능합니다. 발 방향 연속열만 이동하고 옆가지는 남습니다.
- 게임의 보이지 않는 좌표 경계를 제거했습니다. 토끼와 지지 열은 Space를 누를 때마다 계속 이동할 수 있습니다. 카메라는 토끼가 화면 밖으로 벗어나지 않게 따라갑니다. 점유/지지면/무중력 검사에서 거부된 행동은 보드, 턴, Undo 기록을 바꾸지 않습니다. 별도 보드에서 명시적으로 bounded=true를 설정한 경우에만 경계를 검사합니다.
- 목표는 블록 ID와 면에 붙어 함께 이동합니다. 최종 안정 상태에서 클리어를 판정합니다.
- 실제 결과와 미리보기는 같은 정수 해석기를 사용합니다. Rigidbody나 Physics.gravity는 사용하지 않습니다.

## 스테이지

1. **첫 발자국**: 전후 이동, 제자리 회전, 한 블록 내려찍기.
2. **한 칸의 무게**: 토끼와 세 블록 열의 동시 이동, 옆가지 분리. 시작에서 Space 두 번이면 아래 3개 / 옆 3개의 동률 지점입니다. 여기서 Space는 계속 하강하고, D → W는 옆면으로 갈아탑니다. 기존 Y=-3 제한은 제거했습니다.
3. **새로운 바닥**: 내려찍기 후 새 위치에서 오른쪽의 긴 열에 의해 회전.
4. **천장의 거리**: 빈칸 하나 너머 천장에 끌리지 않는지 확인. 바닥을 연장하고 끝에 목표를 두어 클리어할 수 있게 했습니다.
5. **작은 궤도**: 블록 이동과 벽 위 전후 이동/방향 전환의 복합 경로.

- `GrabbitUI.cs`, `GrabbitUIArt.cs`: 시작/선택/게임/팝업 화면, 벡터 아이콘과 버튼.
- `Assets/Grabbit/Editor/GrabbitVerification.cs`: `GRABBIT > Run core verification` 메뉴에서 로직 검사.
- `GrabbitPlayVerification.cs`: 에디터 전용 프레임별 동시 이동 및 실제 키 입력 검사.
- `GrabbitFlowVerification.cs`: 실제 Mouse/Input System 이벤트로 화면과 팝업을 조작하고 5개 스테이지를 클리어하는 검사.

현재 중력 수정 검증 결과는 `Captures/Grabbit-gravity-revision-verification.txt`에 기록합니다. 이전 화면 전환 검증 결과는 `Captures/Grabbit-flow-verification.txt`에 있습니다. 이전 메커니즘 검증 원본은 `Captures/Grabbit-mechanics-verification.txt`에 있습니다.
